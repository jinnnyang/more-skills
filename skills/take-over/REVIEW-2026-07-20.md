## Rejected Alternatives

Considered and NOT recommended:

1. **Rewrite SKILL.md from scratch to be shorter.** — The workflow is genuinely 7-step protocol; brute-shortening loses the branch logic. Better to keep body length and fix only the first screen.
2. **Merge PROTOCOL.md into SKILL.md.** — PROTOCOL.md is a shared contract between hand-off/take-over and cited by ADRs; folding it into SKILL.md would break the ADR reference model (see `references/adr-and-decisions.md` §2). Keep them separate.
3. **Split take-over into `take-over-init` + `take-over-resume` skills.** — Would force users to know which one to invoke; the current single-skill "auto-branch on list-scopes result" is a better UX. The complexity is real but landing it inside one skill is the right call.
4. **Add a `--dry-run` flag to take-over itself (from PROTOCOL.md §13).** — Attractive but adds another branch to the already-branchy Step 0. Better to keep dry-run at the `reconcile.py` command level where it already exists on `clean-up`.
5. **Auto-run `hand-off` alongside `take-over` at session end.** — Violates the "each skill independently installable" invariant established 2026-07-17. Cross-linking via greeting text (R31) is the right level.
