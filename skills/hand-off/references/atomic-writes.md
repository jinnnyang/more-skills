# Atomic Write Rule

> Loaded by hand-off Step 2 when the agent needs to persist any of the four core documents to disk.

## Why atomic

The reconcile helper always writes to `<filepath>.tmp` first, then renames to the target atomically. This guarantees that a crash mid-write cannot leave the doc half-updated — either the old version is intact or the new version is fully in place. Never bypass this via direct `open(..., "w")` in shell.

## Three supported input patterns

Pick based on payload size and escaping complexity.

### 1. Small edits — `--content`

Best for < 4 KB payloads with no complex escaping (no embedded backticks, no newlines that need careful quoting).

```bash
uv run <SKILL_DIR>/scripts/reconcile.py write-atomic \
  --filepath "<scope>/task.md" \
  --content "…"
```

### 2. Multi-line writes — `--content-file` (recommended default)

Stage the content into a temp file, then stream it. This is the safest pattern for anything non-trivial — no shell escaping headaches.

```bash
uv run <SKILL_DIR>/scripts/reconcile.py write-atomic \
  --filepath "<scope>/walkthrough.md" \
  --content-file /tmp/staged.md
```

MSYS-style paths on both `--filepath` and `--content-file` are auto-resolved on Windows (`/tmp/…` → `%TEMP%\…`, `/c/Users/…` → `C:\Users\…`).

### 3. stdin pipe — pipe through

```bash
cat /tmp/staged.md | uv run <SKILL_DIR>/scripts/reconcile.py write-atomic \
  --filepath "<scope>/walkthrough.md"
```

Equivalent to pattern 2 when the payload is already in a file; useful when the payload is being generated by another tool in the same pipeline.

## Frontmatter is preserved

`write-atomic` writes the exact content you pass — it does NOT auto-update `last_updated` / `last_verified` / `last_writer` / `last_agent`. When editing a document that has frontmatter, include the updated frontmatter in your payload. For most hand-off flows, this means loading the current doc, editing the body, re-serialising the whole doc, and passing it back through `write-atomic`.
